# 03. 구현 노트

> 알고리즘 버전 `rule-v1.1` · 2026-09-28

## 1. 점수 구조 (기획서 3장에서 바뀐 점)

기획서 v1은 모든 요소를 한 번에 가중합하는 구조였습니다. 이 구조로 계산해 보니 동해처럼 물때 영향이 작은 해역에서는 하루 종일 점수가 85~92점으로 비슷하게 나왔습니다. 그래서 **"그날 환경"과 "그 시각의 타이밍"을 분리해 곱하는 구조**로 바꿨습니다.

```
env    = Σ w_k · S_k      k ∈ {물때(일간), 바람, 파도, 수온, 기압, 포인트 궁합}
timing = τ · S_물흐름(시간) + (1-τ) · S_광량
score  = 100 · env · (0.5 + 0.5·timing) · (0.35 + 0.65·시즌)
       → 주의(CAUTION)면 ×0.85, 위험(DANGER)이면 최대 15점, 금어기면 0점
```

| 가중치 | 서해 | 동해 |
|---|---|---|
| 물때(일간) | 0.20 | 0.03 |
| 바람 | 0.25 | 0.22 |
| 파도 | 0.18 | 0.30 |
| 수온 | 0.20 | 0.30 |
| 기압 | 0.05 | 0.05 |
| 포인트 궁합 | 0.12 | 0.10 |
| τ (타이밍 안에서 물흐름 비중) | 0.55 | 0.15 |

어종별 보정(`weightBoost`)을 곱한 뒤 다시 정규화합니다. 예를 들어 볼락은 광량 ×1.4, 주꾸미는 물때 ×1.25, 가자미는 물때 ×0.7입니다.

### 하위 점수 요약
- **물때(일간)**: 사리 정도(springness)가 어종의 선호 물때(조금 0.2 / 중간 0.55 / 사리 0.9)에서 얼마나 떨어졌는지로 계산합니다.
- **물흐름(시간)**: 세 가지를 합칩니다. 들물·썰물 선호(45%), 조류 세기 적합도(35%), 물돌이 전후 가점(20%)입니다. 조류 세기는 조위 변화율을 그날 최대값으로 나눠 구합니다. 서해 워킹 포인트는 간조 무렵(조위 하위 20%)에 수심이 얕아지므로 ×0.6을 적용합니다.
- **바람**: 풍속 구간 함수를 씁니다(워킹과 선상은 기준이 다름). 포인트가 바라보는 방향(`facingDeg`)과 풍향의 차이가 60° 미만이면 맞바람으로 보고 −20%, 120° 초과면 등바람으로 보고 +8%를 적용합니다.
- **파도**: 체감 파고는 외해 파고에 포인트 유형별 차폐계수를 곱해 구합니다(내항 0.35, 외항 0.85). 너울(파주기 8초 이상이면서 파고 0.8m 이상)은 ×0.7입니다. 감성돔은 적당한 포말(0.3~0.9m)을 선호합니다.
- **수온**: 적정 수온을 중심으로 한 비대칭 가우시안입니다. 24시간 동안 ±2℃ 이상 급변하면 ×0.75입니다.
- **광량**: 일출·일몰 ±1.25시간은 피딩 시간으로 봅니다. 야간 점수는 월령으로 보정합니다(어두운 밤을 좋아하는 어종 / 밝은 밤을 좋아하는 어종).

### 안전 게이트
| 조건 | 판정 |
|---|---|
| 워킹: 풍속 12m/s 이상 또는 돌풍 17m/s 이상 | 위험 |
| 선상: 풍속 14m/s 이상 또는 파고 2.5m 이상 | 위험 |
| 외항·방파제 끝·갯바위·백사장: 파고 1.5m 이상 | 위험 |
| 같은 곳: 파주기 8초 이상이면서 파고 1.0m 이상(너울) | 위험 |
| 시정 1km 미만 | 선상은 위험, 그 외는 주의 |
| 서해 갯벌·갯바위: 간조 ±1.5시간 | 야간은 위험, 주간은 주의 |

낮 시간(05~20시)의 절반 넘게 위험이면 그날 전체를 "위험"으로 판정하고 대체 포인트를 추천합니다.

### 골든타임
1. 3시간 이동평균을 구합니다.
2. 기준점은 max(65, 그날 최고점 − 12)로 잡습니다.
3. 기준점 이상인 연속 구간을 찾습니다. 위험 시간은 제외합니다.
4. 구간이 4시간보다 길면 합계가 가장 높은 4시간 창으로 좁힙니다.
5. 점수가 높은 순으로 최대 3개를 보여줍니다.

## 2. 천문 계산 (외부 API 없이)
- **신월(삭)**: Meeus 49장 알고리즘을 씁니다(오차 수 분 이내). KST 기준으로 삭이 든 날을 음력 1일로 봅니다. 설날(2026-02-17 = 1일)과 추석(2026-09-25 = 15일)으로 검증했습니다.
- **물때**: 7물때식은 음력 1·16일이 7물, 8·23일이 조금, 9·24일이 무시입니다. 8물때식은 하루 앞서 셉니다.
- **일출·일몰**: NOAA 근사식을 씁니다. 서울 하지 기준 오차는 ±4분 이내입니다.
- **추정 조석**: 달의 시간각에 관측소별 평균고조간격(HWI)을 더하고, 조차는 사리 정도로 대조~소조 사이를 보간합니다. 실제 조석예보와 수십 분 이상 차이 날 수 있어 화면에 "추정"으로 표시합니다. 관측소별 HWI와 조차는 근사값이므로 KHOA 키를 연결해 쓰는 것을 권장합니다.

## 3. 데이터 파이프라인
- 조석예보는 공공데이터포털 `apis.data.go.kr/1192136/tideFcstHghLw`를 호출합니다(옛 바다누리 oceangrid API에서 이전됨). 기상청과 같은 키를 씁니다.
- `getConditions(spot, days)`는 KHOA, KMA, Open-Meteo를 병렬로 호출합니다. 실패한 호출은 notes에 기록하고 다음 소스로 넘어갑니다.
- 캐시는 두 겹입니다. Next.js fetch 캐시(`revalidate` 30분, 조석은 12시간)와 프로세스 메모리 캐시(30분 버킷)입니다.
- 공공데이터포털 API는 일일 호출 한도가 있습니다. 운영 단계에서는 기획서 6장처럼 배치 수집과 DB 저장으로 바꿔야 합니다.

## 4. 검증
- `npm test`로 25개 테스트를 돌립니다. 대상은 음력·물때·일출몰, KMA 격자·파싱, KHOA 파싱, 폴백 체인, 조석 보간, 안전 게이트, 금어기, 가중치, 골든타임입니다.
- 외부 API 실제 호출은 개발 환경의 네트워크 정책 때문에 검증하지 못했습니다. 응답 형식은 목(mock)으로만 확인했으므로 **배포 후 실제 키로 첫 응답을 꼭 확인해야 합니다.**

## 5. 확인이 필요한 항목
- 포인트 좌표와 조위관측소 코드: 대략값입니다. 현장과 KHOA 목록으로 검증해야 합니다.
- 금어기·금지체장: 원문으로 확인한 것은 주꾸미(5/11~8/31)뿐입니다. 나머지는 `verified: false`로 표시하고 공고 링크를 안내합니다.
- 어종 프로필 수치: 통설 기반 초기값입니다. 조황 기록 50건 이상으로 역검증한 뒤 조정해야 합니다.
