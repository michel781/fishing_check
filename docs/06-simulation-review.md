# 06. 시뮬레이션 테스트 · UX/UI 리뷰 · 개선 기획

> 2026-09-30 · 알고리즘 rule-v1.1 → **rule-v1.2**

## 1. 무엇을 어떻게 테스트했나

| 구분 | 방법 | 규모 | 재현 |
|---|---|---|---|
| **엔진 시뮬레이션** | 9개 기상 시나리오 × 12개월 × 전 포인트·어종 × 7일. 안전·금어기·골든타임 **불변식 9개**를 자동 검사하고 분포·변별력·시즌 정합성을 통계로 확인 | 예보 12,096회 / 약 203만 시간 점수 | `npm run simulate` → [engine-report.md](sim/engine-report.md) |
| **UX 시뮬레이션** | 페르소나 7명의 실제 사용 흐름을 브라우저(360·390·1280px)로 실행. 흐름 마찰, 가로 넘침, 터치 대상 크기, 글자 크기, 접근성(axe-core WCAG 2 A/AA) 검사 | 11개 화면 상태 | `npm run ux` → [ux-report-before.md](sim/ux-report-before.md) / [ux-report-after.md](sim/ux-report-after.md) |
| **시나리오 화면 재현** | 앱에 시뮬레이션 모드(`?sim=typhoon&simDate=…&simHour=15`)를 추가해 태풍·너울·해무·냉수대·오후 3시 같은 상황의 화면을 직접 확인 | 9개 시나리오 | 개발 서버 또는 `FISHING_SIM_ENABLED=1` |

**시나리오**: 평상시, 무풍, 한랭전선(강풍), 태풍, 맑은 날 너울(동해), 해무, 장맛비, 냉수대(−6℃), 고수온(+4℃)

**페르소나**
- P1 수도권 주말 워킹꾼: 태안·우럭, 위치 기반 진입
- P2 가족 입문자: 학꽁치, 편의시설 중시
- P3 선상 매니아: 오천항 주꾸미
- P4 동해 루어꾼: 너울 발생일
- P5 현장 사용자: 오후 3시 방파제 위
- P6 태풍 주간
- P7 조황 기록자

## 2. 발견 사항

### 2.1 엔진 (rule-v1.1)

| # | 심각도 | 발견 | 근거(시뮬레이션) | 원인 |
|---|---|---|---|---|
| E1 | 높음 | 오늘의 1순위 골든타임이 이미 지난 시간 | 오후 3시에 열면 **16~57%**가 이미 끝난 구간 | 하루 전체로만 골든타임 계산 |
| E2 | 높음 | 선상 포인트에 한밤 골든타임 | 우럭 골든타임의 **43%**가 20~03시(선상 포함) | 출항 가능 시간 개념 없음 |
| E3 | 중간 | 냉수대에 둔감 | 수온 −6℃에도 **4.7점**만 하락 | 24시간 전 대비만 비교. 여름에는 급강하 후 수온이 적정 범위에 들어가 효과가 상쇄됨 |
| E4 | 중간 | 기본 어종이 그날 최선이 아님 | 시즌 순서 추천이 실제 최고점 어종과 **80%**만 일치 | 날씨·물때를 반영하지 않은 시즌 정렬 |
| E5 | 중간 | 위험일 대체 포인트 공백 | 노출 포인트 **4곳**이 60km 안에 내항 대안 없음(격포·묵호·임원) | 포인트 데이터 부족 |
| E6 | 중간 | 태풍 직후 내항이 89점 | 태풍 다음 날 저녁 내항 최고점 | 폭풍 뒤 탁도·잔너울을 반영하지 않음 |
| E7 | 정보 | 불변식 위반 0건 | 안전·금어기·비시즌 상한 모두 통과 | — |

## 3. 개선 기획과 설계 논리

| 발견 | 개선 설계 | 이유 |
|---|---|---|
| E1·U2 | 날짜 요약에 `remainingBest`(남은 시간 최고점)와 `nextGolden`(지금 이후 첫 골든타임)을 추가. 오늘은 이 값으로 판정·표시하고, 지난 구간은 흐리게 "지남"으로 표시 | 사용자는 "지금부터 갈 가치가 있나"를 묻는다 |
| — | 남은 골든타임이 없을 때(오후 3시 기준 77%) **"그나마 나은 시간"**(연속 2시간 최고 평균)을 제시 | "없음"만 보여주면 결정에 도움이 안 됨 |
| E2 | 선상은 **04~17시만 유효**(그 외 25점 상한, 골든타임 후보 제외). 시간대 가용성을 `available` 플래그로 일반화 | 출항하지 않는 시간 추천은 신뢰를 깎음 |
| E3 | 수온 급변을 **72시간 최고·최저 대비**로 보고, 수온 점수가 아니라 **전체 활성도 배수**로 적용(−4℃ ×0.6, −2℃ ×0.82, +3℃ ×0.9) | 어류는 절대 수온보다 급변에 반응한다. 적정 범위 안이어도 급강하 뒤에는 먹이 활동이 멈춤 |
| E6 | **폭풍 직후** 배수: 지난 24시간 안에 풍속 14m/s 이상 또는 파고 2.5m 이상이었다면 ×0.72 | 태풍 뒤 탁도·잔너울 |
| E4·U8 | 포인트의 모든 어종을 계산해 **그날 점수 순으로 어종 탭 정렬**, 탭마다 점수·⚠·금어기 표시. 기본 어종 = 그날 1위 | 비교가 한눈에, 추천 정확도 100% |
| E5 | 격포항 내항, 묵호항 내항, 임원항 내항 추가. 대체 추천은 **같은 활동(워킹↔선상) 우선**, 원래 포인트보다 점수가 높은 곳만 | 워킹 낚시꾼에게 "선상 가세요"는 대안이 아님 |
| U1 | **"지금" 카드**: 현재 점수, 물 흐름(↗들물/↘썰물), 다음 만조·간조까지 남은 시간, 바람·파도·수온, 진행 중이거나 다음 골든타임. 차트에 "지금" 선을 긋고 지난 시간은 흐리게 | 현장 사용자의 1순위 질문 |
| U3·U4 | 홈 **"어디 갈까"** 카드: 해역(전체/서해/동해) × 날짜 탭 [오늘(남은 시간) · 토 · 일] × 상위 5곳. 위험 비율이 절반을 넘으면 탭에 ⚠, 카드에 "출조 자제" 경고. 신규 `/api/ranking` | 첫 화면에서 "언제·어디"를 결정 |
| U5·U6 | 포인트 찾기: 검색(항구·지역·어종), **초보·가족**(내항 또는 화장실·주차가 있고 테트라포드 없는 워킹 포인트), 화장실, 주차, 야간, 가까운 순 | 입문자·가족 |
| U7 | `/guide` 용어·도움말(물때·사리·조금·들물·물돌이·조차·유의파고·너울·냉수대), 점수 읽는 법, 안전 수칙. 머리글과 바다 정보 카드에 링크 | 입문자 이탈 방지 |
| U9 | 포인트 화면에 "📝 조황 기록" 버튼, 기록 화면이 포인트·어종을 미리 선택. 저장 후 "그 시각 예측 N점 — 맞았어요/보정에 반영" 피드백 | 기록 → 보정 순환 |
| U11 | 골든타임마다 **캘린더(.ics) 추가**(90분 전 알림 포함) | 앱 설치·푸시 없이 알림 |
| U12·U13 | 위험일은 숫자 대신 "⚠ 위험", 노출 포인트·선상·주의/위험일에는 **안전 수칙 카드**(구명조끼, 테트라포드, 들물 고립, 너울, 해경 122) | 안전이 점수보다 먼저 |
| U14 | 포인트 상세 **로딩 뼈대 화면**. 제목 옆 **데이터 배지**(공식 예보 / 예보 모델 / 조석 추정 / 데모 / 시뮬레이션) | 신뢰도를 먼저 알림 |
| U10 | PNG 아이콘 192·512·maskable·apple-touch 180, 앱 바로가기(포인트 찾기·조황 기록) | 설치 품질 |
| A1~A4 | SVG `<title>` 사용, 상태색을 글자용(4.5:1 이상)과 표시용으로 분리, 주요 버튼 배경을 #256abf로(5.2:1), 7일 줄은 스크롤 없는 7칸 그리드, 모든 터치 대상 44px 이상, 차트 글자 12px | WCAG 2.1 AA, 장갑 낀 손 |

## 5. 남은 과제 (다음 기획)

| 우선순위 | 과제 | 이유 / 메모 |
|---|---|---|
| P1 | **기상청 특보(풍랑·강풍·태풍) API 연동** → 안전 게이트 | 지금은 예보 수치로만 판정. 공식 특보가 가장 확실한 신호 |
| P1 | **조위관측소 실측 수온** 연동 (같은 공공데이터포털 키) | 모델 수온 → 실측으로 정확도 향상. [05 기획](05-realtime-fish-signals.md) 1단계 |
| P1 | 랭킹 **첫 요청 지연**(캐시가 없을 때 1~3초, 실제 API는 더 김) | 서버 캐시(Upstash Redis 등)로 인스턴스 간 공유하고, 외부 스케줄러로 10분마다 미리 계산. Vercel Hobby 크론은 하루 1회 제한이라 외부 스케줄러가 필요 |
| P1 | 조황 기록 **서버 저장 + 간편 로그인** | 실시간 어군 신호(FPI)의 핵심 데이터 |
| P2 | Web Push 알림 (즐겨찾기 골든타임, 특보) | iOS는 홈 화면 설치 시에만 지원. 지금은 캘린더 알림으로 대체 |
| P2 | 지도 화면 (카카오맵 키) | 포인트 탐색. 지금은 목록 + 가까운 순 + 카카오맵 길찾기 링크 |
| P2 | 공유 미리보기 이미지(OG) | 카카오톡 공유 시 점수 카드. 한글 폰트 번들 필요 |
| P2 | 어종 확장(갈치·한치 야간 선상, 삼치·방어) | 야간 선상은 `BOAT_HOURS` 예외 프로필로 처리 |
| P3 | 오프라인 모드 고도화 | 즐겨찾기 포인트 예보를 미리 캐시 |

## 6. 재현 방법

```bash
npm test                      # 단위·시나리오 테스트 38개
npm run simulate              # 엔진 대량 시뮬레이션 → docs/sim/engine-report.md

# UX 시뮬레이션 (시뮬레이션 모드 켜고 서버 실행)
FISHING_OFFLINE=1 npm run build
FISHING_SIM_ENABLED=1 npm start -- -p 3100 &
BASE_URL=http://localhost:3100 LABEL=after npm run ux   # → docs/sim/ux-report-after.md, 스크린샷 docs/sim/shots-after/
```

시뮬레이션 모드 예시(개발 서버):
- `/spot/hajodae-rock?sim=swell&simHour=9` — 동해 너울일 갯바위(위험 → 대체 내항 제안)
- `/?sim=typhoon` — 태풍 주간 홈(주말 탭 ⚠)
- `/spot/sinjin-outer?simHour=15` — 오후 3시 현장(지금 카드, 지난 골든타임 흐림)
- `/spot/jumunjin?sim=coldwater&simDate=2026-08-05` — 여름 냉수대
