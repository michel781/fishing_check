# 05. 실시간 어군 출몰·물고기 유무 신호 연동 기획

> 작성일 2026-09-29

## 1. 전제: "지금 여기 물고기가 있다"를 알려주는 API는 없다

어군은 물속에서 움직이기 때문에 **직접 관측하려면 어군탐지기(소나)나 수중카메라가 현장에 있어야** 합니다. 국내외 공공 API 중 특정 방파제 앞 어군을 실시간으로 알려주는 것은 없습니다.

따라서 기획의 핵심은 **간접 신호를 겹쳐서 "지금 있을 확률"을 추정**하는 것입니다.

```
  (1) 살 만한 환경인가?        (2) 실제로 잡히고 있나?        (3) 배들이 몰려 있나?        (4) 직접 보이나?
  수온·수온전선·엽록소·    →   조황 기록·위판량·      →    어선 활동 밀도        →    어탐기·수중카메라
  냉수대·해파리·적조            선사 조황
  ─────────────────────────────────────────────────────────────────────────────────────────────
  빠르고 넓음, 정확도 낮음                                              느리게 확보, 정확도 높음
```

신호 하나하나는 약합니다. 하지만 **"환경이 맞다" + "근처에서 잡혔다" + "평소보다 위판량이 늘었다"**가 겹치면 신뢰도가 크게 올라갑니다.

## 2. 신호 계층별 연동 후보

### 계층 A. 서식 환경 — "살 만한 조건인가" (실시간~일 단위)

| 데이터 | 제공처 | 갱신 | 키·조건 | 어떻게 쓰나 |
|---|---|---|---|---|
| 조위관측소 **실측 수온** | 국립해양조사원(공공데이터포털) | 1~10분 | 공공데이터포털 키 | 모델 수온을 실측으로 대체. 어종 적정 수온 판정의 핵심 |
| 해양관측부이 최신 관측 | 국립해양조사원(공공데이터포털) | 30분 내외 | 공공데이터포털 키 | 외해 파고·수온. 너울 판단 |
| 실시간 수온정보(RISA) | 국립수산과학원 | 30분~1시간 | 수과원 OpenAPI 신청 | 양식장·연안 밀집 해역 수온. 서해 남부·남해 보강 |
| 냉수대·고수온 속보 | 국립수산과학원 | 수시(여름) | 수과원 OpenAPI | 동해 냉수대가 발생하면 해당 해역 **급감점** |
| 해파리·적조 속보 | 국립수산과학원(해파리정보는 공공데이터포털) | 주간·수시 | 공공데이터포털 키 | 대량 출현 시 감점과 경고 |
| 위성 수온·엽록소, 수온전선 | Copernicus Marine Service | 일 1회 | 무료 계정, 출처 표기 | **수온전선(온도가 급변하는 경계)**과 엽록소가 높은 곳은 먹이가 모여 회유어(삼치·방어·고등어)가 붙는 곳 → 해역 단위 가점 |

**산출: 서식 적합도 H(0~1)**
어종의 적정 수온, 전선과의 거리, 엽록소, 부정 요인(냉수대·해파리)을 합쳐 계산합니다.

### 계층 B. 공식 전망 — "이번 주/시즌 흐름" (일~분기 단위)

| 데이터 | 제공처 | 갱신 | 어떻게 쓰나 |
|---|---|---|---|
| 바다낚시지수 | 국립해양조사원(공공데이터포털) | 일 단위, 포인트·어종별 5단계 | 우리 점수와 비교하는 **기준선**. 차이가 크면 원인 분석 |
| 해어황 정보·어황 예보 | 국립수산과학원 | 주간~분기(예: 대형선망 고등어 어황 예보) | 시즌 강도 보정(올해 고등어가 평년의 90% 등) |

### 계층 C. 실제 어획 증거 — "지금 잡히고 있나" (시간~일 단위, 가장 중요)

| 데이터 | 제공처 | 갱신 | 어떻게 쓰나 | 주의 |
|---|---|---|---|---|
| **사용자 조황 기록** | 우리 앱 | **실시간** | 포인트 반경 5~10km, 최근 24~72시간 기록을 시간 감쇠로 합산 | 서버 저장·로그인이 필요. 위치는 반경으로 흐려서 공개 |
| **수협 위판량**(위판장별 위탁판매 현황) | 해양수산부(공공데이터포털) | 일 단위(전일) | 위판장 × 어종의 위판 중량을 **평년 같은 주 대비 이상치**로 탐지. 예: "보령 주꾸미 위판 +45%" → 인근 포인트 가점 | 상업 어선은 조업 해역이 넓음 → 해역 단위 신호로만 사용 |
| 선사·낚시점 조황 | 제휴 | 수시 | 선상 조과(어종·마릿수)를 구조화된 입력으로 받음 | **무단 크롤링 금지** → 제휴 API나 입력 폼으로 확보 |

### 계층 D. 어선 활동 — "배들이 모여 있나" (수일 지연)

| 데이터 | 제공처 | 갱신 | 어떻게 쓰나 | 주의 |
|---|---|---|---|---|
| Global Fishing Watch 4Wings API (추정 조업 활동) | Global Fishing Watch | 수일 지연 | 연근해 조업 밀집 격자 → 회유성 어종의 해역 전망 | **비상업 용도만 허용**. 유료화하면 별도 라이선스 협의 필요. 소형 연안 어선은 AIS가 빠질 수 있음 |

### 계층 E. 직접 관측 — "눈으로 확인" (실시간, 파트너십)

| 방법 | 방식 | 비고 |
|---|---|---|
| 선사 어군탐지기 화면 | 제휴 선사가 출조 중 "어군 확인" 버튼이나 사진을 올림 | B2B 제휴 모델과 연결 |
| 개인용 무선 어탐기 | 사용자가 앱에 "어군 확인" 기록(수심·위치) | 공개 API가 있는 제품은 드묾 → 수동 입력부터 |
| 항·방파제 CCTV | 지자체·어항 CCTV 링크 | 영상 분석은 후순위, 링크만 제공 |

## 3. 계산 모델: 어군 출몰 지수 (FPI, Fish Presence Index)

현재 피싱 인덱스(언제 가면 좋은가)와 **별도**로 "지금 그 근처에 고기가 붙어 있나"를 나타내는 지수를 둡니다.

```
사전확률  P0  = 시즌(월별) × 서식적합도 H × 공식 전망 보정 B
증거 점수 E   = Σ w_i · signal_i · e^(−Δt/τ_i) · e^(−d/λ_i)
                 (i = 사용자 조황, 선사 조황, 위판 이상치, 어선 밀집, 직접 관측)
FPI           = 로지스틱( logit(P0) + E )            → 0~100
신뢰도        = 증거 개수와 최신성으로 상/중/하
```

- **τ(시간 감쇠)**: 사용자 조황 24시간, 위판량 72시간, 어선 밀집 5일
- **λ(거리 감쇠)**: 사용자 조황 5km, 위판장 30km, 어선 격자 20km
- **증거가 없으면** FPI는 사전확률(환경 기반)만 반영하고 신뢰도 "하"로 표시합니다. 추측을 단정처럼 보이지 않게 하기 위해서입니다.
- **최종 추천 점수**는 기존 피싱 인덱스에 FPI를 곱하는 방식으로 결합합니다. 예: `최종 = 피싱인덱스 × (0.7 + 0.3·FPI/100)`

### 화면 표현 (예)

```
┌──────────────────────────────┐
│ 🐟 주꾸미 출몰 신호  강함 (82) │
│ 신뢰도 ●●○                     │
│ · 어제 보령 위판 1.4t (평년 +45%)│
│ · 18시간 전 조황 3건 (반경 6km)  │
│ · 수온 20.8℃ 적정               │
└──────────────────────────────┘
```

알림 예: "즐겨찾기한 오천항 주꾸미 신호가 '보통'에서 '강함'으로 올랐어요"

## 4. 시스템 구조

```
[Vercel Cron / 스케줄러]
  ├─ 10분: 조위관측소 실측 수온, 부이
  ├─ 1시간: 수과원 실시간 수온, 특보
  ├─ 1일 06시: 위판량(전일), 바다낚시지수, 해파리·냉수대
  ├─ 1일: Copernicus 수온·엽록소 → 수온전선 계산 (Python 워커, 예: Cloud Run Job)
  └─ 수시: 사용자·선사 조황 (앱 API)
        ↓
[PostgreSQL + PostGIS (Supabase 등)]
  signal(id, kind, species_id, geom, value, observed_at, source, confidence)
  baseline(kind, species_id, region, week_of_year, mean, std)   -- 평년 대비 이상치 계산용
        ↓
[FPI 계산 (포인트 × 어종, 1시간마다)] → fpi_cache
        ↓
[앱: 포인트 상세 "출몰 신호" 카드, 지도 히트맵, 알림]
```

현재 앱은 DB 없이 요청마다 계산합니다. FPI를 붙이려면 **데이터베이스와 정기 수집(Cron)**이 필요합니다. 이것이 다음 개발 단계의 기반 작업입니다.

## 5. 단계별 로드맵

| 단계 | 기간 | 내용 | 추가 키·계약 |
|---|---|---|---|
| **1. 기반** | 1~2주 | Supabase DB, Vercel Cron, 조황 기록 서버 저장(간편 로그인), 실측 수온 연동 | 공공데이터포털 활용신청 추가(실측 수온, 부이) |
| **2. 증거 신호 v0** | 2주 | 사용자 조황 기반 FPI, 위판량 연동과 평년 대비 이상치, 해파리·냉수대 감점, 바다낚시지수 비교 | 공공데이터포털(위판, 해파리, 낚시지수), 수과원 OpenAPI |
| **3. 위성 환경** | 2~3주 | Copernicus 수온전선·엽록소 → 서식 적합도, 회유어(삼치·방어·고등어) 해역 전망 | Copernicus Marine 무료 계정 |
| **4. 제휴** | 분기 | 선사 조황 입력 도구, 어군 확인 기록, 알림 | 선사·낚시점 제휴 계약 |
| **5. 학습** | 데이터 누적 후 | 조황 기록을 정답으로 FPI 가중치 학습(로지스틱 회귀 → GBM) | — |

## 6. 성공 지표
- **FPI 적중률**: FPI "강함"일 때 조황 성공(1마리 이상) 비율 ≥ 65%, "약함"일 때 ≤ 35% → 구분력이 있는지 확인
- 조황 기록 수: 주당 100건 이상(이 수치가 있어야 실시간 신호가 성립)
- 알림 클릭률 ≥ 10%

## 7. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 조황 기록이 적으면 실시간 신호가 비어 있음(콜드스타트) | 초기에는 위판량·환경 신호 비중을 크게. 기록 보상(배지·통계) |
| 포인트 노출로 인한 과밀·훼손 | 조황 위치를 반경으로 흐리게 표시하고, 개인 기록은 기본 비공개 |
| 허위·광고성 조황 | 사진·시간 검증, 신고, 작성자 신뢰도 가중치 |
| 위판량은 상업 어선 데이터라 워킹 낚시와 괴리 | 해역 단위 보조 신호로만 사용(가중치 제한) |
| 라이선스(GFW 비상업, Copernicus 출처 표기) | 무료 단계에서만 사용하고, 유료화 전 약관 재검토 |
| 공공 API 사양 변경 | 파싱을 방어적으로 작성하고, 수집 실패 알림, 데이터 신선도 표시 |
