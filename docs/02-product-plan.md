# 02. 서비스 기획 — 피싱체크 (fishing_check)

> 한 줄 정의: **"언제, 어디서, 무엇을" — 서해·동해 바다낚시 출조 결정 엔진 (반응형 모바일 웹 / PWA)**

---

## 1. 서비스 목표와 원칙

| 원칙 | 설명 |
|---|---|
| **결정 우선** | 숫자를 나열하지 않고 "가라/말라/여기로 바꿔라"와 **골든타임 구간**을 먼저 보여줌 |
| **안전 게이트 > 점수** | 풍랑특보, 너울, 강풍이면 점수와 관계없이 "위험"으로 표시하고 대체 포인트(내항)를 제시 |
| **근거 공개** | 점수마다 "왜"(물때 4물 +, 북서풍 9m/s −)를 칩으로 보여줌 → 신뢰 확보 |
| **3초 판단** | 첫 화면에서 스크롤 없이 오늘·내일·주말 판단 |
| **설치 없는 공유** | URL 하나로 단톡방 공유. OG 이미지에 점수 카드를 표시 |
| **법규 내장** | 금어기, 금지체장, 금지구역 자동 경고 |

## 2. 핵심 기능 (우선순위)

### P0 — MVP

1. **포인트/지역 선택**: GPS 근처 또는 검색(항구명, 방파제명). 즐겨찾기.
2. **피싱 인덱스(0~100) + 5단계 등급**: 포인트 × 어종 × 시간(1시간 단위) 기준.
3. **골든타임 타임라인**: 오늘~D+3의 시간대별 점수 히트바, 만조/간조, 물돌이, 일출/일몰 마커.
4. **물때 카드**: 물때(7/8물때식 토글), 조차, 만조/간조 시각, 조위 그래프.
5. **바다날씨 카드**: 풍속·풍향(포인트 기준 맞바람/등바람), 파고·파주기, 수온(실측+추세), 강수.
6. **안전 게이트 & 대체 추천**: 특보나 위험 조건이면 "외항 X → 인근 내항 ○ (점수 62)".
7. **어종 카드**: 시즌, 적정 수온, 추천 채비·미끼, **금어기·금지체장 배지**.
8. **주간 출조 캘린더**: 7일 × 추천 어종 매트릭스. "이번 주 최고의 날" 하이라이트.

### P1 — 출시 후 1~2개월

9. **알림(Web Push)**: "즐겨찾기 포인트 토요일 골든타임 85점" 또는 "풍랑주의보 발효".
10. **조황 기록(Catch Log)**: 어종, 마릿수, 시간, 사진 → **알고리즘 보정 데이터**.
11. **포인트 상세**: 내항/외항 구분, 발판, 주차, 화장실, 출입통제, 야간 가능 여부, 등지는 풍향.
12. **공유 카드**: 날짜·포인트 점수 카드 OG 이미지.

### P2 — 성장기

13. 커뮤니티 조황 피드(위치는 반경으로 흐리게 표시해 포인트 보호)
14. 선사 연동(선상 예약, 출항 여부)
15. CCTV/실시간 영상 링크
16. 개인화: 내 조황 기반 가중치(내가 잘 잡는 물때)
17. 조황 로그 기반 ML 모델(학습형 가중치)

## 3. 피싱 인덱스 알고리즘 (v1 — 룰 기반, 설명 가능)

### 3.1 구조

```
FishingIndex(spot, species, t) =
    SafetyGate(spot, t)                    // 0(차단) 또는 1
  × Season(species, date)                  // 0.0 ~ 1.0 (비시즌이면 상한 제한)
  × 100 × Σ wᵢ · Sᵢ(spot, species, t)      // 하위 점수 가중합, Σwᵢ = 1
```

| 하위 점수 Sᵢ (0~1) | 계산 요지 |
|---|---|
| **S_tide 물때** | ① 일간: 물때 번호 → 어종별 선호 곡선(예: 우럭은 조금~5물 피크) ② 시간: 물돌이 ±1h 가점, 들물/썰물 선호, 조류속도(dh/dt) 적정 범위 |
| **S_wind 바람** | 풍속 구간 점수 × 풍향 보정(포인트 `shelter_dirs`와 비교해 맞바람 −) |
| **S_wave 파도** | 유의파고 구간 점수. 포인트 유형별 임계치가 다름(내항은 관대, 갯바위는 엄격) |
| **S_temp 수온** | 어종 적정 범위 중심에서 멀어질수록 가우시안 감점, 24h 변화 ±2℃ 이상이면 감점 |
| **S_light 시간·광량** | 해뜰녘·해질녘 ±1h 가점. 야행성 어종은 야간 가점, 월령 보정 |
| **S_pressure 기압** | 3h 변화량(약한 가중치) |
| **S_spot 포인트 적합도** | 포인트 유형 × 어종 선호(예: 광어 × 모래 선상 = 1.0, 광어 × 내항 = 0.3) |

### 3.2 해역별 기본 가중치 (초기값)

> 구현 시 "환경 × 타이밍" 곱 구조(rule-v1.1)로 바뀌었습니다. 최신 가중치는 [03. 구현 노트](03-implementation.md)를 보세요.

| 가중치 | 서해 | 동해 |
|---|---|---|
| w_tide | **0.30** | 0.10 |
| w_wind | 0.20 | 0.20 |
| w_wave | 0.15 | **0.25** |
| w_temp | 0.15 | **0.25** |
| w_light | 0.10 | 0.10 |
| w_pressure | 0.03 | 0.03 |
| w_spot | 0.07 | 0.07 |

어종 프로필에 따라 한 번 더 보정합니다(예: 볼락은 w_light↑, 주꾸미는 w_tide↑).

### 3.3 안전 게이트 (하나라도 걸리면 `DANGER`, 점수 표시 대신 대체 추천)

- 해당 해역에 **풍랑·강풍·태풍 특보** 발효 중
- 갯바위/외항/방파제 끝: 파고 ≥ 1.5m 또는 (파주기 ≥ 8s AND 파고 ≥ 1.0m) → 너울
- 워킹 전체: 풍속 ≥ 12 m/s
- 갯벌 포인트: 간조 전후 + 일몰 이후(고립 위험) → 경고
- 시정 < 1km(해무) → 선상 경고
- 출입통제구역, 낚시금지구역 → 추천에서 제외

### 3.4 골든타임 산출

1. 1시간 단위 점수 → 3시간 이동평균 후 **상위 구간을 연속 블록으로 병합**
2. 블록 ≥ 70점이면 "골든타임", 50~69점이면 "무난"
3. 출력 예: `토 04:30–07:10 · 87점 · 근거: 초들물 + 해뜰녘 + 북서풍 4m/s(등바람) + 수온 16.8℃`

### 3.5 보정 전략 (v2 이후)

- 조황 로그(어종, 마릿수, 시간, 위치) + 당시 환경변수 스냅샷을 저장
- 조황 성공(마릿수 ≥ N) 여부를 레이블로 삼아 **로지스틱 회귀 / GBM**으로 가중치를 학습하고, 룰 점수와 블렌딩
- KHOA 바다낚시지수와의 상관을 모니터링(콜드스타트 기준선)
- A/B 테스트: 가중치 버전별 "골든타임 적중률"(해당 구간 조황 비율)

## 6. 기술 아키텍처

```
[Client: Next.js(App Router) PWA · TypeScript · Tailwind]
      │  SSR/ISR 페이지 · Service Worker 오프라인 캐시 · Web Push
      ▼
[API: Next.js Route Handlers (또는 NestJS 분리)]
      │  /api/spots, /api/index?spot&species&from&to, /api/fish
      ▼
[Scoring Engine (TS 패키지, 순수 함수 · 단위 테스트)]
      │
[PostgreSQL + PostGIS]  ←  [Redis 캐시: 점수 결과 1h TTL]
      ▲
[Collector 배치 (cron / Cloud Scheduler)]
   ├─ KHOA 조석예보: 매일 03:00, D+30 선수집
   ├─ KHOA 부이/조위 실측: 30분
   ├─ KMA 단기예보: 02·05·08·11·14·17·20·23시 +10분
   ├─ KMA 해상예보·특보: 30분
   ├─ KHOA 바다낚시지수: 하루 2회
   └─ 점수 사전계산(즐겨찾기 상위 포인트 × 어종 × D0~D3)
```

- **호스팅**: Vercel(프론트/API) + Supabase 또는 Neon(Postgres+PostGIS) + Upstash Redis → 초기 비용 최소화
- **지도**: 카카오맵 JS SDK 또는 네이버 지도(국내 해안선, 항구 POI 품질) — 무료 쿼터 내 운영
- **좌표 변환**: 기상청 단기예보는 LCC 격자(nx, ny)라서 포인트마다 사전 변환해 저장
- **포인트 ↔ 관측소 매핑**: 가장 가까운 조위관측소, 부이, 해상예보구역을 PostGIS `ST_DWithin`으로 계산해 저장
- **공공 API 키 보호**: 서버에서만 호출. 클라이언트는 자체 API만 호출
- **관측**: 수집 실패 알림(Slack Webhook), 데이터 신선도 표시("수온 32분 전 관측")

## 8. MVP 범위와 로드맵

| 단계 | 기간(예상) | 산출물 |
|---|---|---|
| **0. 데이터 검증** | 1주 | 공공 API 키 발급, 조석·단기예보·부이 수집 PoC, 포인트 30곳 매핑 |
| **1. 엔진** | 2주 | 스코어링 엔진 v1 + 단위 테스트(골든 케이스: 과거 조황 50건 역검증) |
| **2. MVP 웹** | 3주 | 홈, 포인트 상세, 어종 카드, 주간 캘린더, 안전 게이트, PWA |
| **3. 클로즈드 베타** | 2주 | 서해(태안·보령·안산·인천) 20곳 + 동해(속초·주문진·삼척·포항) 20곳, 낚시 카페 베타 50명 |
| **4. 공개 출시** | — | Web Push, 조황 기록, 공유 카드 |
| **5. 고도화** | 분기 | ML 보정, 남해·제주 확장, 선사 연동 |

**MVP 제외(명시)**: 커뮤니티 피드, 결제, 선사 예약, 로그인 필수화(즐겨찾기는 로컬 저장 → 로그인 시 동기화).

## 9. 성공 지표 (KPI)

| 지표 | 목표(베타) |
|---|---|
| 주간 재방문율(WAU/MAU) | ≥ 40% (출조 결정은 매주 반복되는 행동) |
| 금요일~토요일 새벽 트래픽 비중 | 모니터링(핵심 사용 순간 검증) |
| **골든타임 적중률** | 조황 로그 중 골든타임 구간 내 조과 비율 ≥ 60% |
| 공유 클릭률 | 세션당 ≥ 5% |
| 점수 정확성 피드백("맞았어요") | ≥ 70% 긍정 |
| 푸시 구독률 | 방문자의 ≥ 15% |

## 10. 수익 모델 (후순위)

1. **무료**: D0~D3 점수, 기본 알림
2. **프리미엄(월 2,900~4,900원)**: D+7 상세, 무제한 즐겨찾기 알림, 개인화 가중치, 광고 제거
3. **B2B**: 선사·낚시점 제휴(출항 정보, 조황 게시, 예약 수수료), 낚시용품 제휴 링크(어종 카드 채비 추천)
